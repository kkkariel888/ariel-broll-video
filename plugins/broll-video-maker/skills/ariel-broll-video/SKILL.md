# 口播配动画 B-roll（Claude Code / Claude 桌面 app / Cowork / Codex 通用）

**第一件事**：用户一开口，先回一句「收到，开工：……大概多久」，再去读文件、跑命令（10 秒内必须有这句）。

**永远用中文回复**（大白话；关键帧、渲染这类常用词照用）。不管字幕、风格说明、报错是不是英文，对话里每一句都用中文，一句英文都不要说。

**说话方式**：少说话，直接干活。不寒暄、不解释流程。10 秒内回第一句，之后每个阶段一句进度。能让用户点的就不让用户打字；真要问，一次只问一个问题。

本 skill 文件夹里有：
- `scripts/highlight_server.py`：本机页面小助手：标黄 → 选风格（3×3 样图）→ 审稿表 → 成片（只用 Python 自带库）
- `scripts/wait_page.py`：门铃，用户在页面上一点就把你叫醒
- `scripts/lemo.py`：下载 / 更新 Lemo-Opuscar 风格库，列出能用的风格
- `scripts/render.py`：把画面页渲染成关键帧图或视频（Python 自带库 + 本机 Chrome + ffmpeg；视频默认 1080P 60 帧；`--batch` 一批并行出、自动质检）
- `scripts/transcribe.py`：没有 SRT 时在本机把口播听写成字幕，有逐字稿就用逐字稿纠字；有 SRT 时加 `--times-only` 只量每个字是第几秒说的（SenseVoice，只用 CPU，不上传；Claude Code、Cowork、Codex 都能跑）
- `scripts/beats.py`：让画面跟着说话的快慢走：`make` 给每一处写节拍（每个字第几秒说、哪里停顿，画面页用 `at()` / `cue()` 卡时间）；`voice` 给成片配原声预览。全在后台，不给用户看
- `scripts/dna.py`：参考图量 10 色色卡（`palette`）和主色、量剪辑节奏、查 GitHub 许可证、存进「我的素材库」
- `scripts/ghlib.py`：「我的 GitHub 库」：存用户看中的整套 GitHub 风格库（链接 + 风格描述 + 介绍页里的 3 张预览图）
- `scripts/fonts.py`：下载风格说明里点名的开源字体（下一次永久用，一次下好几个；画面页用 `/@fonts/…` 地址直接读，不复制）
- `scripts/shots.py`：审稿分镜：查 AI 按完整句子切的分组有没有漏字乱序、按逐字时间算每张逐帧图的时间、写审稿表
- `scripts/card.py`：从风格说明里抽出「风格要点卡」（画静态样图要的几节），不花 token，样图子任务只读它
- `scripts/kit.py`：每个风格的「画图工具」存起来重复用（选定风格后写一次，以后正式画面、下次再用都直接拿）
- `assets/highlighter.html`：页面本体（① 标黄 ② 选风格 ③ 审稿 ④ 成片）
- 两个永久的库（在用户电脑上，跨每一期视频）：**我的素材库** `~/lemo-my-styles/<slug>/`（单个风格 + 3 张样图）；**我的 GitHub 库** `~/.broll-video-maker/github/<作者>__<仓库>/`（整套风格库的链接和预览图）。「备选」只是这一期临时比一比，不是库。
- `references/style-dna.md`：参考图提炼风格的规矩；`references/open-source-review.md`：开源项目核验记录

## 两个文件夹（先记住，后面都用这两个名字）
- `<用户的文件夹>`：用户给的那个。**最后里面只多一个 `B-roll成片/`**，别的什么都不放；而且要等用户在「④ 成片」点了「没问题，放进文件夹」（或在对话里说没问题）才放。
- `<工作>` = `<用户的文件夹>/.broll/`（隐藏文件夹）：字幕、标黄、样图、画面页、逐帧图、事件记录……所有中间文件都放这里。下面写的相对路径都在 `<工作>` 里。

## 门铃：用户在页面上一点，你就被叫醒（不用用户回对话）
页面上的每一下都记进 `<工作>/事件.jsonl`。`python3 <本skill>/scripts/wait_page.py <工作> --for 种类1,种类2` 会一直等到用户点了其中一种才返回，打印点了什么，最后一行 `STATUS=event`（等太久是 `STATUS=timeout`，再跑一次接着等）。
- **Claude Code / Claude 桌面 app 的 Code 页面**：用后台运行（`run_in_background`）。你照常干活，用户一点你就会收到通知，读它的输出接着做。每次要等新的点击，就再后台跑一个。
- **Codex**：没有后台叫醒，先把不用等用户的活干完，再直接（前台）跑它，用户在页面一点它就返回。跟用户说「在页面上点就行，不用回我」。
- **用户在对话里回也算**：比如回「就第一个」「没问题出片」「存」「放进文件夹」——你就替他按页面上的按钮：`curl -s -X POST <页面地址>api/act -d '{"act":"pick","slug":"…"}'`（act 和页面按钮一一对应：mode / format / source / pick / more / shortlist / save_style / approve_all / export）。两边结果一样。
- 事件种类：`mode`（文字多 / 动画多）`format`（视频格式，带 `aspect` `size` `quality`）`source`（风格从哪来，带 `kind`：ai / mine / github）`confirm`（点了「开始做」）`pick`（选定风格）`more`（再来 3 个风格）`shortlist`（备选里加 / 减）`save_style`（加入素材库）`approve_all`（审稿没问题，出片）`export`（成片没问题，已放进文件夹）。

## 时间和进度（体验标准，每次都照这个来）
- 用户发完消息 **10 秒内**回第一句（「收到，开工：先听写字幕，大概 30 秒」），再去跑命令。
- **不许超过 30 秒没动静**：每进一个阶段在对话里说一句在干什么、大概多久；页面上也会显示进度。
- 能并行的都并行（下面每一步都写了怎么并行）；能让用户在页面点的，不让他打字。整个过程最多停下来问 2 次。

## 第 0 步：开工前（几秒，和第 1 步的听写同时跑）
先看一眼用户的文件夹：至少要有 1 个口播视频（`.srt` 和逐字稿 `.docx/.txt` 都是可选的）。没有视频或有好几个，按文末「出错了怎么办」处理，**先别下载风格库**。建好 `<工作>` 文件夹。下面 0–2 和第 1 步的听写**一起开跑**（后台），不要一个等一个：
0. `python3 <本skill>/scripts/update_check.py`：查新版本。最后一行是 `STATUS=live` → 说一句「用上了新版 X」，然后读它打印的 `LIVE_SKILL_DIR` 里的 `SKILL.md`，**这次就按新版做**（之后 `<本skill>` 都指那个文件夹）；`updated` / `outdated` 说一句；其他不吭声。
1. `python3 <本skill>/scripts/lemo.py ensure`：第一次会把 Lemo-Opuscar 下载到 `~/lemo-opuscar`（约 30MB），以后只更新。
   **必须下载成功才能画样图。** 失败就把原因告诉用户（多半是连不上 GitHub），等用户说「重试」。Cowork / Codex 沙盒里直接说「要放开 github.com 和 codeload.github.com」。没有保底风格，不要自己凑。
2. 检查 `git`、`ffmpeg`、Chrome（或 Edge / Chromium）。缺了就**直接帮用户装**（Mac：`brew install ffmpeg git`；Linux / Cowork / Codex 沙盒：`apt-get install -y ffmpeg git chromium`；能跑仓库根目录的 `install.sh` 就跑它）。要用户本人点的（Mac 弹窗、输开机密码）才叫用户，不要假装做完。

## 第 1 步：字幕 + 审错别字
- 用户的文件夹里有口播视频，可能有剪映导出的 `.srt`、逐字稿（`.docx/.txt/.md`）。用户也可能顺手给了：参考图、GitHub 风格链接、「用上次那个」。
- **字幕从哪来**：有 `.srt` 就用它的字和时间，**同时后台跑** `python3 <本skill>/scripts/transcribe.py <视频> --times-only --out <工作>`：只量每个字是第几秒说的（`逐字时间.json`），字幕不动。剪映 SRT 只精确到一行，没有它画面就跟不上一行里面的快慢。不用等它，第 5 步才用得上。没有 `.srt` 就**马上**后台跑 `python3 <本skill>/scripts/transcribe.py <视频> [--script <逐字稿>] --out <工作>`。不要叫用户去剪映电脑版导出，也不要按字数估时间。第一次会自动装听写引擎（约 20MB）、下模型（约 160MB），先说一句「第一次要装听写工具，两三分钟」；以后 7 分钟视频约 20 秒。它生成 `字幕_自动识别.srt` 和 `逐字时间.json`（每个字说出来的那一秒，第 5 步让关键词在说到的那一刻出现就查它）。`STATUS=script_mismatch` 就告诉用户逐字稿好像不是这一期，问要不要只用听写结果。
- `ffprobe` 读帧率、时长（只用来对时间、提醒原片太糊）。**画幅不再照原片自动定**：用户在标黄页第 3 步自己选（`<工作>/格式.json`：`aspect` 9:16 / 16:9 / 3:4 / 1:1，`size` 1080x1920 / 1920x1080 / 1080x1440 / 1080x1080，`quality` 1080p / 4k）。不要在对话里问画幅，页面上选。
- 只改错别字和听写错误，不改说法、不加标点、不动时间轴。原文件不动，另存 `<工作>/字幕_修正.srt`。对话里用小表告诉用户：时间 | 原来 | 改成（没改就不列）。

## 第 2 步：打开页面（标黄 + 顶上 4 步）
0. **改错字、分段落、挑标黄一遍读完一起做**（第 1 步的错别字和这里的分段、建议标黄是同一次读字幕，不要读两遍）。目标：听写完 1 分钟内页面打开。
0.5 **按意思分段落（很重要，直接影响用户看着舒不舒服）**：口播稿本来就是一段一段讲的，页面上的段落要和用户讲的段落一致。读完整篇，判断每次换话题、换一个点的地方，写 `<工作>/分段.json`：每段第一条字幕是 SRT 里的第几条（从 1 数），比如 `[1, 4, 9, 15]`。规则：
   - **一句话绝不能切成两段**。剪映字幕一条常常只是半句（还没有标点），所以分段点只能放在一句话说完、下一句另起头的那条字幕上。
   - 一段讲一个意思，一般 2～8 句；开场白、每个要点、举的例子、总结各自成段。别按停顿或字数切。
   - 写完**必须自查**：`python3 <本skill>/scripts/highlight_server.py <工作>/字幕_修正.srt --out <工作> --check-paras`。它打印每两段的交界处「上一段结尾｜下一段开头」，逐条读：读起来是同一句话（比如「…想象成 ｜ 一场长达50年的接力赛…」）就是切错了，挪分段点再查，直到每个交界都是两句完整的话。
1. 按时长定数量：视频秒数 ÷ 6 取整，最少 3 处、最多 15 处。挑建议做 B-roll 的地方（有数字、有步骤、有对比、概念抽象、最想让观众记住的），原文一字不差写进 `<工作>/建议标黄.json`（字符串数组）。
2. 后台启动（**照抄这条，末尾的 `&` 不能少**——它是常驻小助手，前台跑会一直卡住不返回）：`nohup python3 <本skill>/scripts/highlight_server.py <工作>/字幕_修正.srt --suggest <工作>/建议标黄.json --out <工作> > <工作>/_server.log 2>&1 &`（它自动读 `<工作>/分段.json` 分段落），然后 `sleep 2; cat <工作>/_server.log` 拿地址（「标黄页面已启动：http://…」那行，以它为准）。成片目录自动是 `<工作>` 的上一层，也就是用户的文件夹。
3. 在侧边浏览器打开地址（见文末「在哪打开」）。**整个过程用户只用这一个标签页**：之后页面重启、换地址都在这个标签页里跳转（navigate），不新开标签；样图、画面页、对比图一律用 `render.py` 出成 png 自己看，不在浏览器里打开 html 文件；子任务也不许开浏览器标签。重启小助手先关掉旧的（`kill $(lsof -ti tcp:<端口>)`），再用同一个 `--port` 起，地址不变。对话里只说一句：
   > 标黄页面：<地址>（右边已打开）。顶上 4 步按顺序选：标黄 → 文字多还是动画多 → 视频格式 → 风格从哪来，选好点「开始做」。

   **地址一定要写出来**：Codex、Claude Code 命令行里用户只能点这个地址打开页面。
4. 后台跑门铃 `wait_page.py <工作> --for confirm`，只等「开始做」。页面会自己拦住没选完的步骤（标橙色「还差这一步」），你不用管。
   - **标几处、标多长都由用户定**：只标 1 处、一整段很长都行。**不要提醒、不要劝、不要问「要不要多标几处 / 拆短一点」**。
   - **用户划一次就是一处**（页面上一个 B 编号）：紧挨着划两次就是两处，不会合并；一次划过两段文字也还是一处。之后一处 = 一段视频，**AI 不合并、不重拆**；审稿时一处按一两句切成几张图（见第 5 步）。
   - 等的同时可以先做不依赖用户选择的准备：`lemo.py catalog`、读完整份字幕想这期的气质。**用户点「开始做」之前不画样图**（字多字少、画幅都还没定）。

## 第 3 步：3 个风格 × 同 3 句话 = 9 张样图（2 分钟内，并行画）

收到 `confirm` 后先读 `<工作>/格式.json`（画布尺寸 = `size`，下面所有 `--size` 都用它）、`模式.json`、`风格来源.json`，按 `kind` 走：
- `mine`（用户在「我的素材库」里选好了一个）→ `风格选择.json` 已经写好，**跳过第 3 步，直接第 5 步**。对话里说一句「用素材库里的『X』，直接开始画分镜」。
- `github`（用户选了「我的 GitHub 库」里的一个库）→ 见下面第 2 条：从 `风格来源.json` 的 `local`（仓库已下载在本机）里挑 3 个最适合这期的风格。
- `ai` → 照下面的顺序挑。

### 风格从哪来（按这个顺序）
1. **用户给了参考图** → 按 `references/style-dna.md` 提炼风格 DNA，写成新风格放 `<工作>/风格草稿/<slug>/`，排第 1；再从 Lemo 挑 2 个长相差别大的。
2. **用户给了 GitHub 风格链接，或在第 4 步选了「我的 GitHub 库」里的库** → 库里的仓库已下载好（`风格来源.json` 的 `local`，许可证结果在 `~/.broll-video-maker/github/<作者>__<仓库>/repo.json` 的 `verdict`），不用再查；对话里新给的链接先 `python3 scripts/dna.py license <链接>` 查许可证，**查完马上在对话里说一句结果**（比如「许可证查过了：MIT，可以用」），用户才放心：「可以用」/「分块看」读它的风格说明，只在这台电脑上给这期视频用，不存进本 skill；「有限制」告诉用户限制；「不能用」直接说，换别的来源。仓库是一整个风格库（很多风格卡、没有单个 `STYLE.md`）→ 挑 3 张最合适的卡当 3 个候选，`style_md` 指向那张卡；名字起中性的（比如「白板手绘」），不用品牌、作品、角色名。`source` 写 `github`、加 `"repo":"作者/仓库"`。没有许可证的库（`不能用`）：只借它的感觉自己画，不照搬它的任何素材、代码、图片。
3. **用户说「用上次那个」** → 读 `~/.broll-video-maker/last.json`，`curl` 替他点 `pick`（或写 `风格选择.json`），跳到第 5 步。
4. **都没给** → `python3 scripts/lemo.py catalog`（一行一个风格，约 20KB；已去掉要 AI 生图的风格；用户存进素材库的风格也在里面）。**不要用 `--out` 读完整版**（100KB，慢）。读完整份字幕，判断这期在讲什么、语速、气质，挑 **3 个**：第 1 名最稳，第 2、3 名和它长相差别要大。

### 挑 3 句、先占位
- 从标黄（用户还在改就用建议标黄）里挑 **3 句最有代表性、类型不同的原话**：一句带数字、一句讲原理 / 概念、一句讲结论或动作。**3 个风格画同样这 3 句**，用户才能横着比。
- 马上写 `<工作>/风格排名.json`，样图路径先写好（文件还没有，页面会显示「画图中」，画好一张自动出现一张）：
  ```json
  {"size":"1080x1920","sentences":["原话1","原话2","原话3"],"drawing":true,"candidates":[
    {"slug":"dark-keynote","name":"暗色科技发布","source":"lemo","style_md":"~/lemo-opuscar/styles/dark-keynote/STYLE.md",
     "why":"一句话：为什么适合这期","samples":["风格样图/dark-keynote_1.png","风格样图/dark-keynote_2.png","风格样图/dark-keynote_3.png"]}
  ]}
  ```
  `source` 是 lemo / mine / dna / github（页面「选风格」按来源分页签）。每个候选再加一句 `"look":"长什么样：……"`（大白话描述画面，页面上显示）。

**挑风格时考虑速度（第一次用的风格）**：`kit.py status` 是 `ready` 的（以前用过）优先进 3 个候选；第一次用的风格里，少挑人物 / 火柴人 / 复杂插画类（容易画崩、最慢）。用户点名的照用。

### 准备（挑好 3 个风格马上做，全部几秒内）
1. **字体一次下齐**（后台）：把 3 个风格 `STYLE.md` 里点名的字体名找出来，加上中文字体（没点名就 `Noto Sans SC`），`python3 scripts/fonts.py get "字体1" "字体2" …`。下过的秒过；第一次要下的先说一句「第一次用这几个字体，要下载一两分钟」。**样图就用风格指定的正式字体，不拿系统字体凑。**
2. **风格要点卡**：`python3 scripts/card.py <md1> <md2> <md3> --out <工作>/风格卡`。脚本把每本风格说明里画静态图要的几节（本质、材质、配色、字体、常用手法、坑）抽成一张卡，不花 token，一秒出。
3. `python3 scripts/kit.py status <slug1> <slug2> <slug3> --style-md <md1> <md2> <md3>`：`ready` 的风格，子任务可以直接用画图工具（`/@kits/<slug>/kit.js`），更快更统一；`missing` / `stale` 的**样图阶段不写画图工具**（选定以后再写，见第 5 步）。

### 并行画：9 张图同时画（目标 2 分钟出齐）
- **一张图一个子任务，9 个一起派**（Claude Code / 桌面 app 用 Agent 工具，一条消息里 9 个一起发，用平时干活的模型，不降级；Codex 能开子任务就开，不能就自己一个风格一个风格画、画好一个风格报一个）。每个子任务只拿：这一张图的风格卡路径（`ready` 的再给 `KIT.md` 和 `/@kits/<slug>/kit.js`）、这一句原话、它是这个风格的第几张、模式、字体地址（`/@fonts/…`）、画布尺寸、`<工作>` 路径、要写的文件。要求写进给它的话里：
  1. **只读风格卡**，不读整本 `STYLE.md`、不下载东西、不看演示片源码、不写画图工具。
  2. 模式已经定了（`模式.json`）：`anim` 少放字，`text` 可以多放字。
  3. 写一张静态定格页 `风格样图/页面/<slug>/<k>.html`：内容按这句话的意思专门设计（不是套模板），长相严格照风格卡（配色写死卡里的色号、字体用卡里点名的）。**不写 `render(t)` 动画**，画好设 `window.READY=true`。同一个风格的 3 个子任务拿的是同一张卡、同一个画图工具，所以长相统一。
  4. 出图：`python3 scripts/render.py 风格样图/页面/<slug>/<k>.html --at 0 --size <尺寸> --out 风格样图/页面/<slug>/草稿_<k>.png`（自动质检默认开）。有「质检：…」**只改一次**；然后把草稿移到 `风格样图/<slug>_<k>.png`（这一下页面上就出现了）。
  5. **限时 2 分钟**：到时间就交当前最好的一版，回一句「交了，哪里还不够好」。精修留到选定以后。
- **派完马上**在 `风格排名.json` 写 `"eta_s":120,"t0":<现在的 Unix 秒>`（页面显示「约还要 X 秒」），对话里说一句「9 张同时在画，约 2 分钟，画好一张右边出一张」。
- **先到先报**：哪个风格的 3 张先齐了，马上说一句「『X』的 3 张好了，可以先看；其余约 N 秒」。超过 3 分钟还没齐，说一句卡在哪个风格、还要多久，**不干等**。
- 9 个都回来后，把 `风格排名.json` 的 `drawing` 改成 `false`。对话里只说一句「样图在右边：看中了点『就这个』，拿不准先点『备选』再比一比」。**不要在对话里一张张发图**（页面上一屏看完，点开放大）。
- 页面上每个风格 3 个按钮：「就这个」（选定）、「备选」（这一期临时放进对比栏，在「备选里比一比」里一列一个风格并排看）、「加入素材库」（永久存，下次标黄页第 4 步直接选）。备选和加入素材库都不用你管，页面自己处理。
- 后台跑门铃 `wait_page.py <工作> --for pick,more`：
  - `more` → 再挑 3 个和已有的都不一样的风格，**追加**进 `candidates`（之前的都留着），同样准备 + 并行画同 3 句。
  - `pick` → 第 4 步。

## 第 4 步：读结果
- `标黄结果.json`：`confirmed` 为 true 才继续（没确认就后台等 `confirm`，**不要替用户确认**）；`result` 每项是 `no`（B1…）、`text`、`startTime` / `endTime`（秒）。
- `风格选择.json`：`slug`、`name`、`source`、`style_md`、`mode`（text / anim）、`repo`（GitHub 来的）。
- `格式.json`：`size`（画布）、`quality`（`4k` 出片时加 `--scale 2`）。
- 用户如果在对话里粘贴了「标黄结果（共 N 处）：…」，就用粘贴的内容。

## 第 5 步：画每个画面 + 页面上审稿（并行）
1. **画图工具**：`kit.py status <slug> --style-md <md>`。`ready` → 直接用。`missing` / `stale` → 现在写（用户刚点「就这个」，对话里说一句「先把这个风格的画图工具做好，约 2 分钟，之后每段并行画」）：**照用户选中的那 3 张样图页面**（`风格样图/页面/<slug>/1-3.html`）提炼，再补读 `STYLE.md` 讲动效 / 节奏 / 转场的几节，写 `kit.js` + `KIT.md`（要求见「画面页怎么写 · 画图工具」），存：`python3 scripts/kit.py save <slug> <文件夹> --style-md <STYLE.md>`。照着样图提炼 = 用户选中的长相就是成片的长相。「用上次那个」跳过了样图：没有工具就按 `STYLE.md` 写一份；字体照样先 `fonts.py get`。需要的话 `lemo.py demo <slug>` 看演示片写法，不照搬故事和画面。这一期额外要的共用零件，加在 `逐帧代码/共用.js` 里（从 kit 引入，不复制 kit 的内容）。
2. **用户标的每一处就是一个画面，不合并、不拆**：`标黄结果.json` 里 B1、B2… 一处对应一个画面页、一段视频；审稿图按「一两句完整的话」一张，全片连续编号 1、2、3…，用户说数字就知道改哪张。
3. **先量好节拍**（几秒）：`python3 <本skill>/scripts/beats.py make <工作>`，每一处得到 `逐帧代码/节拍/B3.js`（每个字第几秒说、哪里停顿、每个短句从第几秒开始）。这是后台自己用的，**不给用户看、不要用户确认**。它打印「按字幕行估的」时（听写没跑成），对话里说一句「这次画面只能跟到每句话，跟不到每个字」。
3.5 **一处标黄一个画面页、一个子任务，全部一起派**（超过 8 处就每个子任务管 2 处）：每处一个 `逐帧代码/B3.html`，**画面跟着说话的快慢走**（硬规定，写进每个子任务的要求里）：
   - 页面先引用节拍：`<script src="节拍/B3.js"></script>`（放在自己的脚本前面），`window.DUR = BEAT.dur`（= 这一处说话的时长）。
   - 字、数字、图标、线条的出现，一律用 `cue("那个词")` 当开始时间：动作比说到早 0.25 秒开始，词说出来时刚好到位。要知道说到的那一秒用 `at("词")`，说完用 `endOf("词")`；同一个词第二次出现 `at("词", 2)`。词要照原话写（`BEAT.text` 里有）。
   - 换画面、转场放在 `BEAT.pauses`（说话停顿）或 `BEAT.phrases`（换短句）的时间点上；说得快画面就密，停顿时画面停住等。
   - **不许自己估时间、不许把时间平均分**；出审稿图时会做「跟嘴检查」，没卡上的会报出来。
用户标的一处很长时，视频里画面可以跟着语速变化（照 `KIT.md` 的转场手法），但它还是一处、一段视频。页面里设 `window.BEATS = true`，`window.KEYTIMES` 用下面「审稿分镜」算出来的（每组一个）。
   **审稿分镜（写画面页之前做）**：读每处原话，按意思切成组，写 `<工作>/分镜.json`（`{"B1":["第一组原话","第二组原话"],…}`）。规矩：每组是**一两句完整的话、能单独画成一个画面**；只在一句话说完的地方切，**不许把上一句的尾巴和下一句的开头拼成一组**，不许按秒数硬切；各组按顺序拼起来必须和原话一字不差。然后跑 `python3 <本skill>/scripts/shots.py <工作> --style <选定的slug>`：查分组有没有漏字、乱序（`STATUS=mismatch` 就改分镜再跑），用逐字时间算出每处的 KEYTIMES（打印出来，也存 `分镜时间.json`），并直接写好 `逐帧审稿.json`。画面页的内容要跟着这些分组换（换组的时间点优先放在 `BEAT.phrases` / `BEAT.pauses` 上）。内容按这一处的意思设计、长相照 `KIT.md`、引用 kit 和 `共用.js`。子任务只读 `KIT.md` + kit.js + 共用.js，不读整本 `STYLE.md`。
4. 全部写完一次出审稿图：写 `逐帧代码/任务.json`（每处 `{"page":"B3.html","keyframes":true,"out":"../逐帧图/B3","size":"<格式.json 的 size>"}`），`render.py --batch 逐帧代码/任务.json --jobs 3`。每处按 KEYTIMES 出几张 `逐帧图/B3/1.png、2.png…`。有「质检：…」先自己改好重出（同一处最多 3 次）；「跟嘴：…」就是那个词说出来时画面没动，改它的 `cue()` 时间点或补上动作。
5. `逐帧审稿.json` 已由 `shots.py` 写好（手写也照下面的格式），页面「③ 审稿」就出现分镜墙：一行几张按画幅和屏幕宽度自动定（图为主、字为辅），每张图下部是白底黑边的字幕框，写「编号 + 这一处的逐字稿原话」（页面自动加编号），框上贴黑色小标签写时间。`text` 只放原话，不加「第几句」之类的前缀；句子再长页面也会自动缩字放下。逐帧图本身不要画这个框（页面会叠上去）。**rows 按 B1、B2… 的顺序，每行 frames 按分镜放几张，每张的 `text` 只写那一两句原话、`time` 写那组开始的时间**（不要一张图配一整段）：
   ```json
   {"size":"1080x1920","rows":[{"no":"B3","text":"这一处完整原话","time":"00:41","page":"逐帧代码/B3.html",
     "frames":[{"img":"逐帧图/B3/1.png","text":"第一两句原话","time":"00:41"},{"img":"逐帧图/B3/2.png","text":"接下来一两句","time":"00:45"}]}],"style":"<画这些图用的风格 slug>"}
   ```
   对话里只说一句「画面都在右边『审稿』里（点图放大，← → 翻页）。没问题点『没问题，出片』；要改哪张，直接在这里说图上的数字，比如『5 数字放大一点』」。
6. 后台跑门铃 `wait_page.py <工作> --for approve_all,pick`（审稿时用户可能回「② 选风格」点「换成这个」，页面会立刻跳回审稿、旧图变灰显示「重画中」）。`逐帧审稿.json` 里一定写 `"style":"<画这些图用的风格 slug>"`，页面靠它判断是不是旧风格的图。同时听对话：
   - 用户说「5 ……」（也可能一次说好几张：「3 和 7 字太小」）→ 看第 5 张属于哪一处（比如 B2），只改那一处的 `逐帧代码/B2.html`，重出它的审稿图（路径不变，页面自动刷新）。**改完说一句「5 改好了，右边再看一眼」**（用户说的数字原样说回去）。接着等。
   - `pick`（换了风格）→ 读新的 `风格选择.json`，回到本步第 1 条，用新风格把每一处重画、重出审稿图，`逐帧审稿.json` 的 `style` 改成新 slug，说一句「换成『X』了，正在重画 N 张，画好审稿里自动换」。
   - `approve_all`（或用户在对话里说没问题 → `curl` 替他点 `approve_all`）→ 第 6 步。**没收到没问题就不出视频**（返工成本最高）。

## 第 6 步：出片（一次并行渲染，先放在工作文件夹里）
- **用户标的一处出一段视频**（B1 一段、B2 一段……），不合并、不拆。
- 写 `<工作>/成片.json`：`{"rendering":true,"clips":[{"no":"B3","file":"成片/B3_00-41.mp4","time":"00:41–00:58","text":"原话","dur":17.2,"trans":"推镜转场"}…]}`（`file` 在 `<工作>` 里；文件名 = 编号 + 开始时间「分-秒」，用户拖进剪映一看就知道放哪），页面「④ 成片」会显示进度，渲染好一段出现一段（小卡片，点开播放）。
- 写 `逐帧代码/成片任务.json`（每处 `{"page":"B3.html","out":"../成片/B3_00-41.mp4","size":"<格式.json 的 size>"}`，`格式.json` 的 `quality` 是 `4k` 就每个加 `"scale":2`，先说一句「4K 出片慢一倍多」），`render.py --batch 逐帧代码/成片任务.json --jobs 3`。**不管原片多糊，一律 60 帧**（render.py 默认；不要传 `--fps` 降下来）。
- 渲染完跑 `python3 <本skill>/scripts/beats.py voice <工作> --video <口播视频>`：给每段配上原声做预览（页面上点开就带你的声音，一听就知道对不对得上）；放进用户文件夹的还是没声音的那份。
- 做完把 `成片.json` 的 `rendering` 改成 `false`，对话里说一句「成片在右边『成片』里，点开看，没问题点『没问题，放进文件夹』」。
- 后台跑门铃 `wait_page.py <工作> --for export`：页面一点，小助手就把这几段复制进 `<用户的文件夹>/B-roll成片/`。用户在对话里说「没问题 / 放进去」→ `curl` 替他点 `export`。用户说某段要改 → 改那段的画面页、重出它（关键帧 + 视频），说一句「B3 改好了」。
- 原片低于 1080P 或低于 30 帧，顺口提醒一句：下次剪映导出口播选 1080P 以上、帧率和拍摄一致。用户要「直接嵌进原视频」再做：整条 60 帧、libx264 -crf 16、音轨直接复制，输出 `B-roll成片/成片_完整版.mp4`。

## 第 7 步：交付
- 收到 `export` 后说：成片在 `<用户的文件夹>/B-roll成片/`，文件名里就是该放的时间点；中间文件在隐藏的 `.broll/` 里，要改某一段再叫我。
- 选的风格不在素材库里，就提一句（这是最后一问）：「这个风格要加入素材库吗？下次标黄页第 4 步直接选。」页面「④ 成片」底下有「加入素材库」，用户点了或回「存」都行（回「存」就 `curl` 替他点 `save_style`）。Lemo / GitHub 的风格只存样图和位置，不复制说明内容。
- 不往桌面另存，不在用户的文件夹里放别的东西。

## 我的 GitHub 库（用户说「把 github.com/xxx 存进我的 GitHub 库」时）
1. 回一句「收到，存进你的 GitHub 库，十几秒」。
2. 先读这个仓库的 README（`dna.py license <链接>` 会把仓库下载到 `~/.broll-video-maker/imports/`，或直接看网页），写一两句大白话 `--desc`：画面大致长什么样、适合讲什么内容；数一下里面大概有几种风格写进 `--count`（比如「约 80 种风格」）。
3. `python3 <本skill>/scripts/ghlib.py add <链接> --desc "风格大致是：……" --count "约 N 种风格" [--name 好记的中文名]`：它查许可证、从介绍页抓 3 张预览图（没有图页面上就显示文字卡片）、存进 `~/.broll-video-maker/github/`。名字起中性的，不用品牌、作品、角色名。
4. 对话里说一句：「存好了：<名字>，许可证 <结果>。下次标黄页第 4 步选『我的 GitHub 库』就能用。」许可证是「不能用」要说清：只能借感觉自己画，不能照搬它的素材。
- `ghlib.py list` 列出存过的库。用户说「删掉 xxx」→ 先问一句确认，再删 `~/.broll-video-maker/github/<作者>__<仓库>/`。

## 不要做的事
| 不要 | 为什么 / 改成 |
|---|---|
| 没有 SRT 时凭感觉编字幕，或叫用户去剪映电脑版导出 | 用 `transcribe.py` 在本机听写（有逐字稿就带 `--script`）。时间轴来自听写，不要手改。 |
| 改用户的原文件（SRT、视频、逐字稿） | 修正一律另存（`字幕_修正.srt`），原文件不动。 |
| 改口播的说法和数字 | 只改错别字。发现数字对不上（比如口播说「省一百五十多个小时」，按它自己的说法算不到），在错别字小表下面提一句，让用户决定。 |
| 用英文回复（哪怕字幕、报错、风格说明是英文） | 对话里一律中文大白话。 |
| 提醒用户「标得太少 / 太长 / 只有一处」、劝他多标或拆短 | 标几处、多长都由用户定。长的自己拆成好几张分镜。 |
| 照原片自动定画幅，或在对话里问画幅、清晰度 | 用户在标黄页第 3 步选，读 `格式.json`。 |
| 没有用户的话就替他点「开始做」、选风格、出片、放进文件夹 | 只有用户在页面点了，或在对话里明说了，才算。用户不在就等门铃。 |
| 逐帧图没确认就渲染视频；成片没确认就放进用户的文件夹 | 成片先放 `<工作>/成片/`，用户点「没问题，放进文件夹」才复制过去。 |
| 在对话里一张张发样图、逐帧图让用户审，或做「换一批」 | 都在页面上：样图一屏看完、审稿是分镜墙，点开放大；试过的风格都留着。对话里只说一句去哪看。 |
| 用户还没点「开始做」就画样图 | 文字多少、画幅都还没定，会画错。 |
| 把用户紧挨着标的几处合成一处，或把用户标的一处拆成几段视频 | 用户划一次就是一处、一段视频。审稿图例外：一处按一两句切成几张，方便逐句审。 |
| 审稿一张图配一大段原话 | 一两句一张，字幕框里只放那一两句。 |
| 逐字稿段落按停顿或字数切，一句话被切到两段 | 写 `分段.json` 按意思分段，并用 `--check-paras` 逐个看交界处。 |
| 让用户回对话说「好了」「选好了」 | 用门铃 `wait_page.py`，页面一点就醒。用户主动在对话里回也照办。 |
| 把字幕、样图、画面页、json 放进用户的文件夹 | 中间文件一律放 `.broll/`，用户的文件夹只多 `B-roll成片/`。 |
| 一个一个串着画、串着渲染 | 样图按风格并行、画面页分组并行、`render.py --batch` 并行出。 |
| 画真实品牌的界面、logo、角色，或用品牌/作品名给风格起名 | 版权风险。风格名起中性的，比如「暗色发布会」。 |
| 把 Lemo 或 GitHub 风格的内容存进本 skill、发给别人 | 只在用户电脑上现读现用（见「版权和致谢」）。 |
| 风格库下载失败时自己凑一个保底风格 | 没有保底风格。告诉用户原因，等用户说「重试」。 |
| 降低画质（crf 大于 16、照原片帧率 / 分辨率出 B-roll） | B-roll 一律 1080P 60 帧。 |
| 画面里的字和动效自己估时间、平均分时间，或只对齐整段的开头结尾 | 用 `beats.py make` 的节拍：`cue("词")` 卡在说到的那一刻，停顿处换画面。 |
| 把节拍、语速、每个字的时间发给用户看或让用户确认 | 全在后台自己用。用户只看审稿图和成片。 |
| 软件没装好却说装好了 | 要用户本人操作的（Mac 弹窗、输开机密码）就直说。 |

## 出错了怎么办（遇到就照做，不要自己绕过去）
| 情况 | 怎么办 |
|---|---|
| 文件夹里没有 `.srt` | 不用停，跑 `transcribe.py`（见第 1 步）。 |
| 有 SRT、后台 `transcribe.py --times-only` 失败 | 不用停：`beats.py make` 会按每行字幕的长短估每个字的时间，对话里说一句「这次画面只能跟到每句话」。 |
| `render.py` 打印「跟嘴：…」 | 那个词说出来的时候画面没动、或页面没用节拍：改那一处的画面页再出，最多 3 次。 |
| `transcribe.py` 装引擎或下模型失败（没有 SRT 时） | 多半是网络被拦（Cowork / Codex 的沙盒）。把它打印的网址告诉用户：要能访问 pypi.org、github.com、objects.githubusercontent.com，请用户在设置里放开后说「重试」。不要改用别的听写办法，也不要按字数估时间。 |
| 没有口播视频 | 停。请用户把口播视频放进文件夹（画幅、帧率、时长都要从视频里读）。 |
| 有好几个 `.srt`、逐字稿或视频 | 用表列出文件名和时长，让用户点一个。不要猜。 |
| SRT 最后一句的结束时间和视频时长差 2 秒以上 | 把两个数告诉用户，问是不是同一期。用户说是再往下走。 |
| `ffprobe` 读不出 | 告诉用户视频可能坏了或格式不支持，请重新从剪映导出。 |
| 标黄小助手起不来 | 端口被占时它会自动换端口，以它打印的地址为准。还起不来就把报错告诉用户，改用对话里粘贴标黄（第 4 步最后一条）。 |
| 侧边浏览器打不开或被别的页面占着 | 把地址发给用户自己点开。 |
| 电脑上没有中文字体 | `python3 scripts/fonts.py get "Noto Sans SC"`（约 17MB，下一次永久用）。下载失败就告诉用户原因，等用户说「重试」；**不要换成系统字体或别的字体凑**，风格就是靠字体撑的。 |
| `render.py` 找不到 Chrome | Mac / Windows：请用户装 Chrome，或者设好环境变量 `CHROME` 指向浏览器。Linux / Cowork / Codex 沙盒：`apt-get install -y chromium`；装不上就告诉用户「出图要浏览器，这一步请到 Claude Code 或桌面 app 的 Code 页面里做」，前面的标黄、选风格结果都在文件夹里，接着做就行。 |
| 渲染出来空白、字出框、元素叠在一起（`render.py` 打印「质检：…」） | 先自己改页面重出，同一张最多改 3 次，再给用户看。还不行，把这张图和问题告诉用户。 |
| `dna.py license` 失败，或 3 分钟没结果 | 告诉用户，让用户点「重试」或「改用 Lemo 风格」。 |
| `lemo.py catalog` 结果是空的 | 重跑一次 `lemo.py ensure`，还是空的就把输出告诉用户，等用户说「重试」。 |
| 用户一直没点「开始做」 | 停下来等。**不要替用户点，也不要先画样图。** 页面上缺哪一步会标橙色「还差这一步」。 |
| `ghlib.py add` 下载失败 | 多半连不上 GitHub，把原因告诉用户，等用户说「重试」。 |

## 画面页怎么写
- 一个 HTML 文件，满足 Lemo 的页面约定：`window.DUR = 秒数`；`window.render = t => {…}`（同一个 t 永远画出同一张，不用定时器、不用 CSS 过渡）；字体图片加载完设 `window.READY = true`；可选 `window.KEYTIMES = [秒数…]`（正式画面：每张分镜一个，配 `window.BEATS = true`）。
- **正式画面要跟着说话走**：引用 `节拍/B3.js`，时间点用 `cue("词")` / `at("词")` / `BEAT.pauses`（见第 5 步第 3.5 条），不手写秒数。
- **风格样图例外**：只出一张定格，不写 `render(t)`，画好设 `window.READY = true`，用 `render.py --at 0` 出图。
- 画布尺寸 = `格式.json` 的 `size`（竖屏 1080×1920、横屏 1920×1080、竖版 3:4 1080×1440、方形 1080×1080），不看原片分辨率（原片 480P 也一样）。选了 4K 就同一尺寸加 `--scale 2`。Canvas 2D 或 DOM 都行；**用 Canvas 必须按 `devicePixelRatio` 建画布**（`c.width = W*devicePixelRatio; ctx.scale(devicePixelRatio, devicePixelRatio)`，CSS 宽高仍是 W×H），否则加 `--scale 2` 出 4K 时会糊。可以 `import` Lemo 的工具：`/core/lib.js`（缓动、弹簧、噪声等，MIT），`render.py` 会从 `~/lemo-opuscar` 提供。
- 字体：照 `STYLE.md` 点名的开源字体，`python3 scripts/fonts.py get "字体名"` 下载（下过就秒过），页面里用它打印的地址加载：`new FontFace('Anton','url(/@fonts/anton/Anton-Regular.ttf)')`。**不要复制到页面旁边**（一个中文字体 17MB）。中文没点名就用思源黑体 / 思源宋体（`"Noto Sans SC"` / `"Noto Serif SC"`）。
- **画图工具（kit）**：每个风格一份，存在 `~/.broll-video-maker/kits/<slug>/`，页面里 `import * as K from '/@kits/<slug>/kit.js'`。
  - `kit.js`（ES 模块，300 行以内）：`C` 配色常量；`fonts()` 加载这个风格的字体（用 `/@fonts/` 地址）；背景 / 纸张 / 质感；这个风格常用的 4～8 个零件（大数字、标题、标签、箭头、卡片、图表、人物剪影……按 `STYLE.md` 的长相画）。零件都写成「给参数画出来」，静态样图和动画画面都能用（动画时传进度 0～1）。可以 `import` Lemo 的 `/core/lib.js`（缓动、弹簧、噪声）。
  - `KIT.md`（20 行以内）：配色、字体、质感、构图、动效、禁忌各一两句，加上 `kit.js` 每个函数一句话。下次用这个风格的子任务只读它就能开画。
  - 只在这台电脑上用，不发给别人、不放进本 skill（风格说明的版权见「版权和致谢」）。
- 画面里不画字幕条（字幕在剪映里统一加）；竖屏底部 1/5 不放关键内容，给字幕留位置。
- 不画任何真实品牌的界面、logo、角色；风格说明里写了「不要用它们的名字、界面、字体」的照做。
- 共用的零件放进这个风格的 kit（以后每期都能用）；只有这一期才用的放 `逐帧代码/共用.js`。整期长相一致。

## 参考图 → 风格 DNA（第 3 步第 1 条）
按 `references/style-dna.md`。目标：**像同一个人用同一套手法做的新作品，不像把原图换了个主体**。
- **带走视觉语法**：`dna.py palette 参考图` 量 10 色色卡（3 主 + 5 辅 + 2 点缀，画面只用这些色），AI 看图写光、视角、材质、组织方式、影子质感、字、动（是视频加 `dna.py cuts`）。
- **不带走内容指纹**：原图的具体物件、一眼能认出的物件组合、构图骨架、logo 和文字。画面里的物件从这句口播的意思现想，再用原图的手法画。
- 写成 `style.json`（含 `palette`）+ `STYLE.md` 放在 `<工作>/风格草稿/<slug>/`。每张样图出 `render.py --compare 参考图 样图 --out 对比.png` 自查三条：像不像同一套语言、遮住字能不能认出原图、物件是不是从这句话来的。颜色像原图不算错，不拿程序相似度分数当标准。
- 用户说「再离远一点」→ 换物件或构图，不动色卡；说「太不像了」→ 补上没做到的视觉语法。用户满意：`dna.py save 风格草稿/<slug>` 存进 `~/lemo-my-styles/`（我的素材库），以后和 Lemo 风格一起参与挑选。

## 在哪打开标黄页面
| 环境 | 做法 |
|---|---|
| Codex 桌面 app | in-app browser（侧边浏览器）打开地址 |
| Claude 桌面 app | 内置浏览器（侧边面板）打开地址 |
| Claude Code / Codex CLI | 把地址发给用户点开 |
| Cowork（隔离环境，用户自己的浏览器打不开它的 `127.0.0.1`） | 不发地址。能发布可交互页面就照下面「网页版」的做法；不能就在对话里列出建议标黄的句子（编号 + 原话），让用户用能点的选项勾选、改完回「好了」，结果照第 4 步最后一条处理；风格样图逐张发图，用能点的选项选 |
| Claude 网页版（碰不到用户电脑） | 把 `assets/highlighter.html` 里的 `__DATA__` 换成页面数据，发布成右侧可交互页面并开启页面数据存储（db），确认后读 `transcript/current`；风格在对话里用能点的选项问 |

页面数据格式：`{"title":名称,"blocks":[{"type":"p","text":原文,"hl":[[起,止]],"sug":[[起,止]],"cues":[[字起,字止,秒起,秒止]],"time":"00:12"}]}`。环境变量 `CHROME` 可指定浏览器路径。
