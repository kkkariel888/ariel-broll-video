# 口播配动画 B-roll（第四版 · Claude / Codex 通用）

**说话方式**：少说话，直接干活。不寒暄、不解释流程、不复述用户的话。只在真正需要用户决定时才问，而且一次只问一个问题。用中文、大白话。

本 skill 文件夹里有：
- `scripts/highlight_server.py`：标黄小助手（只用 Python 自带库）
- `assets/highlighter.html`：仿 Word 的标黄页面

## 开工：读文件夹
用户会给一个文件夹，里面有：
- 剪映导出的字幕 `.srt`（必需）
- 口播视频（必需）

读视频的宽、高、帧率、时长（用 `ffprobe`）。宽小于高就是竖屏 9:16，否则是横屏 16:9。**不要问用户画幅。** 只有读不出来时，才把画幅放进下面第 3 步那个问题里一起问。

## 第 1 步：审错别字
- 只改错别字和听写错误，比如同音字、专有名词、数字写错。不改说法，不加标点，不改时间轴。
- 原 SRT 不动，另存一份 `字幕_修正.srt` 在同一个文件夹，可以直接导回剪映。
- 在对话里用一张小表告诉用户改了哪些：时间 | 原来 | 改成。没发现错就说一句「没发现错别字」。

## 第 2 步：侧边栏打开仿 Word 文档并标黄
1. 通读修正后的字幕，挑出建议做 B-roll 的地方：有数字的、有步骤的、有对比的、概念抽象的、最想让观众记住的。一条 3 分钟视频一般 8～15 处。
2. 把这些地方的原文照抄（和字幕一字不差）写进 `建议标黄.json`，格式是字符串数组。
3. 在后台启动小助手（它会一直运行，不用等它结束）：
   `python3 <本skill文件夹>/scripts/highlight_server.py 字幕_修正.srt --suggest 建议标黄.json --out <用户的文件夹>`
4. 在侧边栏浏览器里打开它打印的地址（见文末「在哪打开」）。

## 第 3 步：只问一个问题
和错别字表放在同一条消息里，最后只问：

> 右边我先标了 N 处，直接改就行，改好点「确认标黄」。
> 这期 B-roll 想要**文字讲解多一点**，还是**纯动画多一点**？

## 第 4 步：读标黄结果
用户说标好了，读文件夹里的 `标黄结果.json`：
- `confirmed` 为 true 才继续，否则提醒点「确认标黄」。
- `result` 每项是一处：`no`（B1、B2…）、`text`（原文）、`startTime` / `endTime`（在视频里的秒数）。时间直接用，不用再估算。
- 用户如果在对话里粘贴了「标黄结果（共 N 处）：…」，就用粘贴的内容。

## 第 5 步：定风格（不问，直接给样图）
- 根据内容从下面菜单里挑一个最合适的风格，按视频画幅画一张样图，配一句「为什么选它」。
- 用户说「换」，就再给 2 个备选的样图；说「看全部」，就列出菜单；发了参考图，就照着参考图现场写一张新风格卡。
- 定下后写一张风格卡（配色色值、画面元素、动画节奏、禁止清单），整期严格照它来。
- 文字多少按第 3 步的回答来。

**创作者原创**
1. 单线条风：浅色底，细线条一笔画出的图形和图标，一个强调色，留白多。适合讲道理、讲方法。
2. 黑暗极客风：深色底，终端代码感，等宽字体，青绿或亮蓝强调色，打字机效果。适合讲 AI、工具、技术。
3～5. 待定

**开源精选**（改编自开源项目，见文末致谢）
6. 瑞士动态排版：严格网格、一个字体、一个信号色。适合讲结论、框架。
7. 数据叙事：数字一笔一笔画出来，只加一个「为什么重要」的标注。适合讲收益、涨跌。
8. 等距信息图：45 度小方块场景，一块块搭起来。适合讲系统怎么运作。
9. 蓝图 / 工程制图：深蓝底白线。适合讲结构、原理。
10. 象形运动图形：简单小人和图标。适合讲人群、流程。
11. 丝网印刷：两三种专色叠印在暖色纸上。适合讲观点。
12. 16-bit 像素：大像素、有限配色、像老游戏。适合讲故事、周期。
13. 中国水墨：水墨晕染、留白。适合讲历史、东方话题。
14. 扁平矢量讲解：平涂色块和简单角色。适合通用科普。
15. 纸片拼贴：卡纸剪贴、定格式动画。适合讲生活、消费。

所有风格：重要内容避开平台右侧按钮和底部文案的遮挡区；不用真实品牌、名人、受版权保护的角色。

## 第 6 步：逐帧图审稿
- 先出图，全部确认前不渲染视频。
- 每个 B 编号出 1～3 张关键帧：开场、元素最满的一刻、结束定格。
- 一张一张单独发，绝不拼成大图；每张图外边标上编号和原话（如「B3 · 00:41：复利就是利滚利」），标注不进最终视频。
- 用户点名改哪张就只改哪张。确认过的图存进 `已确认逐帧图/`。

## 第 7 步：对齐语速并出片
- 每段动画时长 = 这处标黄的 `startTime` 到 `endTime`；关键词在说到的那一刻出现。
- 用代码写动画（HTML/SVG/Canvas），逐帧算出画面，用 ffmpeg 合成。尺寸、帧率和原视频一致；每段一个文件、同样的编码设置，concat 无损拼接。先渲染 1 段给用户看。
- 让用户二选一：A. 只要动画片段 + 时间表，自己进剪映拼（原片零损失）；B. 直接嵌进原视频（libx264 -crf 16 或更低，音轨直接复制）。
- 画质只能保持或更高。交付前列出原片和成片的分辨率、帧率、码率。
- 文件夹最后有：`字幕_修正.srt`、`标黄逐字稿.docx`、`标黄结果.json`、`已确认逐帧图/`、`成片/`。

## 在哪打开标黄页面（只有这一处因环境不同）
| 环境 | 做法 |
|---|---|
| Codex 桌面 app | in-app browser（侧边浏览器）打开地址 |
| Claude 桌面 app | 内置浏览器（侧边面板）打开地址 |
| Claude Code / Codex CLI | 把地址发给用户点开 |
| Claude 网页版（碰不到用户电脑） | 把 `assets/highlighter.html` 里的 `__DATA__` 换成页面数据，发布成右侧可交互页面并开启页面数据存储（db），确认后读 `transcript/current`，字段同 `标黄结果.json` |

- 页面数据格式：`{"title":名称,"blocks":[{"type":"p","text":原文,"hl":[[起,止]],"sug":[[起,止]],"cues":[[字起,字止,秒起,秒止]],"time":"00:12"}]}`。
- 小助手起不来（如没有 Python）：退回网页版做法；还不行就请用户把要配动画的句子直接发在对话里。
- 缺 ffprobe / ffmpeg 又装不上：直接说缺什么、怎么开权限，不要假装做完。
